## What you see

In the [`dynamic-matrix`](https://github.com/ciatlas/flowpact/tree/main/fixtures/dynamic-matrix) fixture:

```text
▲  WARN  FP402 matrix-key-missing-in-combo
  matrix.shard is undefined in 2 of 3 combinations of jobs.sharded
  ▶ .github/workflows/matrix.yml:33:64
```

## Why it matters

In combinations without the key the value is an empty string. Scripts, env vars and runner labels built from it silently degrade (e.g. `--config=` with no value).

## How to fix

Define the key for every combination, or add a fallback (`${{ matrix.key || 'default' }}`).

## Scope

Not reported: conditions (`if:`) and `continue-on-error`, comparisons and negations (`matrix.key != ''`, `!matrix.key`), `matrix.key && ...` guards, quoted shell tests in `run:` scripts (`[[ -z "${{ matrix.key }}" ]]`, `[ "${{ matrix.key }}" = on ]`), and combinations where the job or step is skipped by its own `if:`.

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the
editor's quick fix adds it there) or at the end of the line, after any other comment such as a version
(`# v4.3.0 # flowpact: ignore[FP402] why`):

```yaml title=".github/workflows/matrix.yml"
# flowpact: ignore[FP402] why it is acceptable here
- run: ./test.sh --suite ${{ matrix.suite }} --shard ${{ matrix.shard }}
```

**In the config**, with an [override](/docs/configuration#overrides), which can expire:

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP402
    target: ".github/workflows/matrix.yml#jobs.sharded.matrix.shard"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP402") | .symbol'
```

`*` matches within a path segment and `**` across segments, so one entry accepts every finding whose symbol matches:
`target: '**#inputs.app-id'` is that input in every workflow and action.
