## Why it matters

An unreadable contract cannot be compared, so drift and breaking changes go unnoticed.

## How to fix

Contracts are generated: resolve the merge by running `flowpact generate` instead of editing the file.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
# .github/flowpact/contracts/workflows/deploy.contract.yaml after a merge
interface:
  inputs:
<<<<<<< HEAD
    environment:

    env:
>>>>>>> main
```

</Tab>
<Tab value="Fixed">

```yaml
# resolve the conflict in deploy.yml, then `flowpact generate` writes the contract again
interface:
  inputs:
    environment:
      type: string
      required: true
```

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and comes back when the date passes ([overrides](/docs/configuration#overrides)):

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP805
    target: <the finding's symbol>
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP805") | .symbol'
```

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP805: off
  # or: contract-invalid: error
```

Explain it in the terminal:

