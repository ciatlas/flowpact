## Why it matters

GitHub resolves a step’s `./path` against the workspace, not the repository. When the path lies in another repository’s checkout, in a checkout of this repository at another ref, outside the workspace, where an earlier step’s script writes, or where no checkout of this repository puts it, flowpact cannot read the action: its inputs, outputs and the path itself are taken on trust.

## How to fix

Nothing to fix if this is intended. To have it checked, reference another repository’s action as `owner/repo/path@ref`, and this repository’s as `$/path` (or check this repository out where the path points).

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
- uses: actions/checkout@v5
  with:
    repository: acme/shared-actions
    path: shared
- uses: ./shared/setup
```

</Tab>
<Tab value="Fixed">

```yaml
- uses: acme/shared-actions/setup@v2
```

</Tab>

## Configure

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP610: off
  # or: workspace-unverified: error
```

Explain it in the terminal:

```sh
flowpact explain FP610
```
