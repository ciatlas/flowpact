## What you see

In the [`broken`](https://github.com/ciatlas/flowpact/tree/main/fixtures/broken) fixture:

```text
✖  ERROR  FP503 schema-violation
  Unexpected value 'stepz'
  ▶ .github/workflows/schema.yml:6:5
```

## Why it matters

GitHub refuses to run a workflow or action with schema errors, often only when the trigger fires. Some keys it accepts and ignores instead, such as a top-level `env:` in action.yml, a filter the event does not support or a YAML merge key under an event. Those are reported as warnings: the file runs, but without the setting. The configured severity caps both kinds, so `FP503: warning` also reports schema errors as warnings, and ignored keys are never reported above warning.

## How to fix

Correct the key or value reported. Most messages come from @actions/workflow-parser, the parser GitHub’s tooling uses; for a key GitHub ignores, the warning says what is lost and how to fix it.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
# action.yml
env:
  UV_VERSION: 0.9.0   # ignored: actions have no top-level env
runs:
  using: composite
  steps:
    - uses: astral-sh/setup-uv@v7
      with:
        version: ${{ env.UV_VERSION }}
```

</Tab>
<Tab value="Fixed">

```yaml
# action.yml
inputs:
  uv-version:
    default: 0.9.0
runs:
  using: composite
  steps:
    - uses: astral-sh/setup-uv@v7
      with:
        version: ${{ inputs.uv-version }}
```

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart, and comes
back when the date passes ([overrides](/docs/configuration#overrides)):

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP503
    file: ".github/workflows/schema.yml"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP503") | .symbol'
```

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP503: off
  # or: schema-violation: error
```

Explain it in the terminal:

```sh
flowpact explain FP503
```
