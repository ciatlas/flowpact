## Why it matters

A reference the lockfile lacks is not checked (unless `--fetch-remotes` or the action’s `remotes: fetch` fetches it for the run). It happens when a reference moves to another version, for example in a pull request from Renovate or Dependabot, until the lockfile is updated. A reference pinned to a full commit SHA (`octo/setup@<sha>`) runs that commit, so an entry that records another one describes other code: it is not used, and the calls are not checked. `flowpact remotes update` never writes such an entry; an edit to the lockfile did. A reference that GitHub’s `.github/workflows/actions.lock` pins runs the commit it records, even after its tag moves: an entry that records another one (the bot that updated `actions.lock` left the lockfile as it was) is still used, though it may describe other inputs than run.

## How to fix

Run `flowpact remotes update` and commit the lockfile (see the Renovate and Dependabot recipes in the docs).

back when the date passes ([overrides](/docs/configuration#overrides)):
