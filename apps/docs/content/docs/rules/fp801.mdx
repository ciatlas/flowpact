## What you see

In the [`broken`](https://github.com/ciatlas/flowpact/tree/main/fixtures/broken) fixture:

```text
✖  ERROR  FP801 contract-missing
  .github/workflows/expressions.yml has no contract (expected .github/flowpact/contracts/workflows/expressions.contract.yaml)
  ▶ .github/workflows/expressions.yml:1:1
```

## Why it matters

Without a locked contract, changes to its interface and wiring are not visible in review and cannot be checked.

## How to fix

Run `flowpact generate` and commit the updated contracts. In CI, the flowpact action (check mode) attaches the regenerated contracts and a `git apply`-able patch to the run — see its job summary.

      type: string

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and comes back when the date passes ([overrides](/docs/configuration#overrides)):

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP801
    target: ".github/workflows/expressions.yml"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP801") | .symbol'
```

`*` matches within a path segment and `**` across segments, so one entry accepts every finding whose symbol matches:
`target: '**#inputs.app-id'` is that input in every workflow and action.

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP801: off
  # or: contract-missing: error
```

Explain it in the terminal:

```sh
flowpact explain FP801
```
