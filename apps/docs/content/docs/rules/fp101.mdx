## What you see

In the [`composite-actions`](https://github.com/ciatlas/flowpact/tree/main/fixtures/composite-actions) fixture:

```text
✖  ERROR  FP101 missing-required-input
  Step tools uses .github/actions/install-tools without required input "versions-file" — GitHub will run it with an empty value
  ▶ .github/workflows/build.yml:11:15
```

## Why it matters

For reusable workflows GitHub fails the run when a required input is missing — even if the input also has a `default`, which is then never used. For composite actions `required` is not enforced at all: the step silently runs with an empty string (or the default), which is how test variants get skipped unnoticed.

## How to fix

Pass the input under `with:`, or mark it `required: false` with a `default` if it is truly optional.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
jobs:
  test:
    uses: ./.github/workflows/test.yml
    with:
      suite: unit
      # "config" is required by test.yml but not passed
```

</Tab>
<Tab value="Fixed">

```yaml
jobs:
  test:
    uses: ./.github/workflows/test.yml
    with:
      suite: unit
      config: release
```

</Tab>
</Tabs>

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the
editor's quick fix adds it there) or at the end of the line, after any other comment such as a version
(`# v4.3.0 # flowpact: ignore[FP101] why`):

```yaml title=".github/workflows/build.yml"
# flowpact: ignore[FP101] why it is acceptable here
uses: ./.github/actions/install-tools
```

**In the config**, with an [override](/docs/configuration#overrides), which can expire:

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP101
    target: ".github/actions/install-tools#inputs.versions-file"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP101") | .symbol'
```

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"

  FP101: off
  # or: missing-required-input: error
```
