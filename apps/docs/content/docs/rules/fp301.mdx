## What you see

In the [`composite-actions`](https://github.com/ciatlas/flowpact/tree/main/fixtures/composite-actions) fixture:

```text
✖  ERROR  FP301 undefined-output-ref
  Step "tools" runs after this step, so its outputs are not available yet
  ▶ .github/workflows/build.yml:9:30
```

## Why it matters

Undefined outputs evaluate to an empty string. Downstream jobs then run with missing versions, tags or flags.

## How to fix

Fix the output name, declare the output on the job/workflow/action, or reference the right job or step. In a composite action, a step writing to `$GITHUB_OUTPUT` sets its own output, not the action's: give the step an `id` and map the output under the action's `outputs:` (`value: ${{ steps.<id>.outputs.<name> }}`).

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
jobs:
  build:
    outputs:
      version: ${{ steps.meta.outputs.version }}
  deploy:
    needs: build
    run: deploy ${{ needs.build.outputs.vesion }}
```

</Tab>
<Tab value="Fixed">

```yaml
    run: deploy ${{ needs.build.outputs.version }}
```

</Tab>
</Tabs>

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the
editor's quick fix adds it there) or at the end of the line, after any other comment such as a version
(`# v4.3.0 # flowpact: ignore[FP301] why`):

```yaml title=".github/workflows/build.yml"
# flowpact: ignore[FP301] why it is acceptable here
- run: echo "tools ${{ steps.tools.outputs.version }}"
```

**In the config**, with an [override](/docs/configuration#overrides), which can expire:

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP301
    target: ".github/workflows/build.yml#jobs.build.steps.tools.outputs.version"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP301") | .symbol'
```

`*` matches within a path segment and `**` across segments, so one entry accepts every finding whose symbol matches:
`target: '**#inputs.app-id'` is that input in every workflow and action.

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP301: off
  # or: undefined-output-ref: error
```

Explain it in the terminal:

```sh

```
