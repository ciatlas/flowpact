## What you see

In the [`contracts-drift`](https://github.com/ciatlas/flowpact/tree/main/fixtures/contracts-drift) fixture:

```text
✖  ERROR  FP803 breaking-interface-change
  Breaking change to .github/workflows/deploy.yml: output "deployed-version" was removed — consumers reading it get an empty value
  ▶ .github/workflows/deploy.yml:3:3
```

## Why it matters

Callers written against the locked interface will fail (unknown or missing input) or silently read empty outputs. In large pipelines those callers may live in other repositories or rarely-run branches.

## How to fix

Update every caller first (flowpact lists the known consumers), then regenerate the contract. If the change is intended, `flowpact generate` records it and the diff makes the break explicit in review.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
# contract: input "channel" optional
on:
  workflow_call:
    inputs:
      channel: { type: string, required: true }   # now required
```

</Tab>
<Tab value="Fixed">

```yaml
# keep it optional with a default (a required workflow_call input ignores its default),
# or update all callers first, then: flowpact generate
      channel: { type: string, required: false, default: stable }
```

</Tab>
</Tabs>

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the
editor's quick fix adds it there) or at the end of the line, after any other comment such as a version
(`# v4.3.0 # flowpact: ignore[FP803] why`):

```yaml title=".github/workflows/deploy.yml"
# flowpact: ignore[FP803] why it is acceptable here
workflow_call:
```

**In the config**, with an [override](/docs/configuration#overrides), which can expire:

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP803
    target: ".github/workflows/deploy.yml#outputs.deployed-version"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP803") | .symbol'
```

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP803: off
  # or: breaking-interface-change: error
```

Explain it in the terminal:

```sh
flowpact explain FP803
```
