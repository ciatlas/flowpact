## What you see

In the [`incident-matrix`](https://github.com/ciatlas/flowpact/tree/main/fixtures/incident-matrix) fixture:

```text
✖  ERROR  FP401 empty-binding-for-matrix-combo
  Input "config" for .github/workflows/run-suite.yml is empty in 1 of 3 matrix combinations — matrix.config is not defined there
  ▶ .github/workflows/tests.yml:23:19
```

## Why it matters

GitHub evaluates a missing matrix key to an empty string — no error, no warning. The affected matrix leg runs with an empty input, so the callee may skip its real work (e.g. a test configuration) while the run stays green.

## How to fix

Define the key in every combination (add it to the `include` entry or a matrix dimension), or add an explicit fallback: `${{ matrix.key || 'default' }}`.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
strategy:
  matrix:
    include:
      - name: linux
        config: ci-linux.json
      - name: windows        # no "config" → empty input
uses: ./.github/workflows/run-tests.yml   # declares config: { required: true }
with:
  config: ${{ matrix.config }}
```

</Tab>
<Tab value="Fixed">

```yaml
    include:
      - name: linux
        config: ci-linux.json
      - name: windows
        config: ci-windows.json
```

</Tab>

## Scope

Reported as an error when the input is required (or the callee is not in the repository) or when its default is empty (none, or `default: ''`) and an `if:` in the callee reads it, and as a warning when the empty value replaces a non-empty `default`. Not reported for other optional inputs (an empty default that no condition reads, or reads only through a fallback such as `inputs.x || 'all'`): the callee handles the empty value like an omitted input.

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the

```yaml title=".github/flowpact/flowpact.config.yml"

  - rule: FP401

    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP401") | .symbol'
```

`*` matches within a path segment and `**` across segments, so one entry accepts every finding whose symbol matches:
`target: '**#inputs.app-id'` is that input in every workflow and action.
