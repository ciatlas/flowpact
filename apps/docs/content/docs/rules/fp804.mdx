## What you see

In the [`contracts-drift`](https://github.com/ciatlas/flowpact/tree/main/fixtures/contracts-drift) fixture:

```text
✖  ERROR  FP804 orphan-contract
  Contract .github/flowpact/contracts/workflows/nightly.contract.yml describes .github/workflows/nightly.yml which no longer exists
  ▶ .github/flowpact/contracts/workflows/nightly.contract.yml:1:1
```

## Why it matters

If the workflow was removed or renamed, anything still calling it (including other repositories) breaks — the stale contract is the last record of that interface.

## How to fix

Confirm nothing depends on the removed workflow, then run `flowpact generate` to delete the contract.

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and comes back when the date passes ([overrides](/docs/configuration#overrides)):

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP804
    target: ".github/workflows/nightly.yml"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP804") | .symbol'
```

`*` matches within a path segment and `**` across segments, so one entry accepts every finding whose symbol matches:
`target: '**#inputs.app-id'` is that input in every workflow and action.

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP804: off
  # or: orphan-contract: error
```

Explain it in the terminal:

```sh
flowpact explain FP804
```
