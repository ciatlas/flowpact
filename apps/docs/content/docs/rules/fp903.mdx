## Why it matters

A heads-up so the owner can finish the follow-up before the build starts failing.

## How to fix

Fix the underlying findings, or extend `expires` with an updated reason.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
overrides:
  - rule: unused-input
    target: .github/workflows/pipeline.yml#inputs.legacy-flag
    reason: Read by the release dispatcher until the migration (JIRA-123)
    expires: 2026-01-31   # within 14 days
```

</Tab>
<Tab value="Fixed">

```yaml
# migration done: the input and the override deleted; or, when it slipped, a new date and why
    reason: The release dispatcher reads it until the migration moves to Q2 (JIRA-123)
    expires: 2026-04-30
```

</Tab>
