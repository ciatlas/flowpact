## What you see

In the [`cycles`](https://github.com/ciatlas/flowpact/tree/main/fixtures/cycles) fixture:

```text
✖  ERROR  FP601 call-cycle
  Call cycle: .github/workflows/b.yml → .github/workflows/c.yml → .github/workflows/b.yml
  ▶ .github/workflows/c.yml:5:11
```

## Why it matters

GitHub rejects recursive reusable workflow calls when the run starts.

## How to fix

Break the cycle by extracting the shared jobs into a separate workflow that neither side calls back.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
# .github/workflows/test.yml, which build.yml calls
on: workflow_call
jobs:
  package:
    uses: ./.github/workflows/build.yml   # build.yml calls test.yml: a cycle
```

</Tab>
<Tab value="Fixed">

```yaml
# .github/workflows/test.yml calls nothing back
on: workflow_call
jobs:
  unit:
    runs-on: ubuntu-latest
    steps:
      - run: npm test
```

</Tab>
</Tabs>

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the
editor's quick fix adds it there) or at the end of the line, after any other comment such as a version
(`# v4.3.0 # flowpact: ignore[FP601] why`):

```yaml title=".github/workflows/c.yml"
# flowpact: ignore[FP601] why it is acceptable here
uses: ./.github/workflows/b.yml
```

**In the config**, with an [override](/docs/configuration#overrides), which can expire:

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP601
    target: ".github/workflows/b.yml"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP601") | .symbol'
```
