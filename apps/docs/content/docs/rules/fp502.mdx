## What you see

In the [`broken`](https://github.com/ciatlas/flowpact/tree/main/fixtures/broken) fixture:

```text
✖  ERROR  FP502 expression-parse-error
  Invalid expression "inputs.mode = 'release'": Unexpected symbol: '='
  ▶ .github/workflows/expressions.yml:10:25
```

## Why it matters

GitHub rejects the workflow when it is triggered, or fails the step that contains the expression.

## How to fix

Fix the syntax: strings use single quotes, `==` for equality, and every `${{` needs a closing `}}`.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
if: ${{ inputs.mode = "release" }}
```

</Tab>
<Tab value="Fixed">

```yaml
if: ${{ inputs.mode == 'release' }}
```

</Tab>

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and does not fail the build.

**On its line**, with an [ignore comment](/docs/configuration#ignore-comments) alone on the line above it (the
editor's quick fix adds it there) or at the end of the line, after any other comment such as a version
(`# v4.3.0 # flowpact: ignore[FP502] why`):

```yaml title=".github/workflows/expressions.yml"
# flowpact: ignore[FP502] why it is acceptable here
if: ${{ inputs.mode = 'release' }}
```

**In the config**, with an [override](/docs/configuration#overrides), which can expire:

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP502
    file: ".github/workflows/expressions.yml"
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP502") | .symbol'
```

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"

  FP502: off
  # or: expression-parse-error: error
```
