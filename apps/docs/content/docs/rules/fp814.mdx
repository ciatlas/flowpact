## Why it matters

For example a check name built from the triggering event, `needs` outputs or `vars`, a matrix computed at runtime, or an output that is now set only when an `if:` holds. flowpact cannot tell whether consumers see a different check name, or run where the output is `''`, so it does not count the change (`impact.uncertain: fail` counts it).

## How to fix

Review the change by hand. Make a check name static (a literal `name:` or one built only from `matrix` and `inputs`); give an output a value on every run (no `if:` on its source, or a fallback such as `${{ steps.m.outputs.v || 'none' }}`), or declare the change as major.

## Example

<Tabs items={["Problem", "Fixed"]}>
<Tab value="Problem">

```yaml
# in a published reusable workflow
jobs:
  test:
    runs-on: ${{ inputs.runner }}   # was ubuntu-latest: which runners callers need is known only at run time
```

</Tab>
<Tab value="Fixed">

```yaml
jobs:
  test:
    runs-on: ubuntu-latest   # or keep the change, and declare it major (feat!: …)
```

</Tab>

## Accept one finding

When a finding is intended, accept it with a reason rather than turning the rule off. It is listed apart from the other
findings, and comes back when the date passes ([overrides](/docs/configuration#overrides)):

```yaml title=".github/flowpact/flowpact.config.yml"
overrides:
  - rule: FP814
    target: <the finding's symbol>
    reason: Why it is acceptable here, at least 10 characters.
    expires: YYYY-MM-DD   # optional
```

`target` is the symbol the finding is about; to list them:

```sh
flowpact lint --format json | jq -r '.findings[] | select(.code == "FP814") | .symbol'
```

An override counts only once it is on the base branch: impact mode reads the overrides and severities of its rules
from the baseline's config, so a pull request cannot accept or switch off its own check. No ignore comment accepts
its findings.

## Change the severity

Change the severity (or turn the rule off) in `.github/flowpact/flowpact.config.yml`, by code or by name:

```yaml title=".github/flowpact/flowpact.config.yml"
rules:
  FP814: off
  # or: impact-uncertain: error
```

A severity counts only once it is on the base branch, as impact mode reads it from the baseline's config.

Explain it in the terminal:

```sh
flowpact explain FP814
```
