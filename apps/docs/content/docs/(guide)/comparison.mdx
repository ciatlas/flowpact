description: What flowpact reports that actionlint and GitHub's VS Code extension do not, with actionlint's and flowpact's output side by side, and where the tools overlap.
---

flowpact reports what happens between files and matrix combinations: values written in the YAML that arrive empty,
with no error from GitHub and nothing from actionlint or GitHub's VS Code extension. It also checks calls into other
repositories against a committed lockfile, in CI too, and grades a new version before you take it. actionlint checks
each file in more depth (shell scripts, expression types, runner labels), so use both.

What each tool reports, from small test repositories and the tools' own documentation:

| Problem | actionlint | GitHub Actions extension¹ | flowpact |
| --- | --- | --- | --- |
| One matrix combination passes an empty value, because an `include` entry lacks a key | — | — | ✓ names the combination ([`FP401`](/docs/rules/fp401), [`FP402`](/docs/rules/fp402)) |
| An optional input with no default is left out: a step is skipped, or a required input further down gets `''` | — | — | ✓ [`FP105`](/docs/rules/fp105), [`FP107`](/docs/rules/fp107) |
| A reusable workflow reads a secret it does not declare | only if it declares other secrets; also reports reads that `secrets: inherit` makes valid | — | ✓ counts the callers that do not inherit ([`FP205`](/docs/rules/fp205)) |
| A step's local action is not where the step runs: a path typo, or a checkout into a subdirectory | — | — | ✓ [`FP606`](/docs/rules/fp606) |
| A composite action reads an input it does not declare | — (does not lint `action.yml`) | — | ✓ suggests the declared name ([`FP108`](/docs/rules/fp108)) |
| An output arrives empty: its step never writes it, or a nested workflow no longer has it | — | nested workflow only | ✓ [`FP304`](/docs/rules/fp304), [`FP301`](/docs/rules/fp301) |
| A matrix built with `fromJSON` is read with a key it never has | — | — | ✓ once you declare its keys ([`FP403`](/docs/rules/fp403), [`FP404`](/docs/rules/fp404)) |
| GitHub rejects the run: a call cycle, a call chain of more than 10 workflows, more than 256 matrix jobs | — | — | ✓ [`FP601`](/docs/rules/fp601), [`FP602`](/docs/rules/fp602), [`FP406`](/docs/rules/fp406) |
| GitHub rejects the run: a job of a called workflow, or of a workflow it calls, requests a `GITHUB_TOKEN` permission the call does not grant | — | — | ✓ names the job and each scope, raises the grant in a quick fix, and checks remote workflows against the [lockfile](/docs/remote-interfaces) ([`FP613`](/docs/rules/fp613)) |
| Inputs, outputs and secrets nothing reads, and which secrets a `secrets: inherit` call actually needs | — | — | ✓ [`FP104`](/docs/rules/fp104), [`FP106`](/docs/rules/fp106), [`FP203`](/docs/rules/fp203), [`FP303`](/docs/rules/fp303), [`FP204`](/docs/rules/fp204) |
| A published workflow changes an input, an output or a check name that consumers in other repositories may depend on | — | — | ✓ against the committed [contract](/docs/contracts) (`FP803`) or the pull request's base in [impact mode](/docs/impact-mode) (`FP810`); it does not read the consumers |
| Where a value comes from and where it goes, across files | — | — (no go to definition or references) | ✓ `flowpact trace`, hover, go to definition, references |
| A workflow reads an `env` variable that nothing sets | — | ✓ also warns on a valid `$GITHUB_ENV` write earlier in the job | only if no action step, such as `actions/checkout`, comes before the read ([`FP501`](/docs/rules/fp501)) |
| A call to a local reusable workflow or local action leaves out a required input or secret, or passes an unknown input or a literal of the wrong type | ✓ | local reusable workflows only, when signed in; no type check | ✓ suggests the declared name ([`FP101`](/docs/rules/fp101)–[`FP103`](/docs/rules/fp103), [`FP201`](/docs/rules/fp201)) |
| A matrix key that no combination defines | ✓ | ✓ | ✓ [`FP404`](/docs/rules/fp404) |
| A `${{ }}` expression that does not parse, or calls a function with the wrong number of arguments | ✓ | ✓ | ✓ [`FP502`](/docs/rules/fp502) |
| A context used where GitHub does not allow it, such as `secrets` in a job's `if:` | ✓ | ✓ | ✓ [`FP505`](/docs/rules/fp505) |
| A call to an action or reusable workflow in another repository leaves out a required input, or passes an input or secret it does not declare | ✓ for popular actions such as `actions/checkout`, from data built into actionlint; not for reusable workflows | ✓ when signed in, against the version on GitHub while you edit; no type check | ✓ against the committed [remote interfaces lockfile](/docs/remote-interfaces), also in CI and without network, with the type of a literal ([`FP101`](/docs/rules/fp101)–[`FP103`](/docs/rules/fp103), [`FP201`](/docs/rules/fp201), [`FP202`](/docs/rules/fp202)); without an entry, a remote reusable workflow call is reported as unverified ([`FP603`](/docs/rules/fp603)) |
| A new version of an action or reusable workflow in another repository breaks one of your calls: a tag moved, or a bot's pull request moves the reference | — | — (it checks the version on GitHub when you next edit the file) | ✓ graded before you take it, on the pull request that moves the reference and in a scheduled drift check ([When a version changes](/docs/remote-interfaces#when-a-version-changes)) |
| A property that a built-in context does not have, such as `github.reff` or `runner.oss` | ✓ | ✓ as a warning | — |
| An expression whose type does not fit, such as `${{ github.ref_name }}` (a string) in `timeout-minutes`, or an object in `${{ }}` | ✓ | — (only a literal such as `${{ 'abc' }}`) | — (only a literal, [`FP503`](/docs/rules/fp503)) |
| A cron schedule that is invalid (hour 25) or runs more often than every 5 minutes | ✓ | ✓ | — |
| A runner label that does not exist, such as `ubuntu-latst`, or was retired, such as `ubuntu-18.04` | ✓ | — | — |
| Bugs in `run:` scripts, such as an unquoted variable | ✓ runs shellcheck when it is installed | — | — |
| Security: script injection, excessive permissions, pinning ([zizmor](https://github.com/zizmorcore/zizmor) covers these) | script injection and hard-coded credentials | not compared | — |

¹ GitHub Actions extension 0.31.5 through its language server; for calls into other repositories, language server 0.3.60
from extension 0.32.3 (2026-10-15). It checks calls to reusable workflows and remote actions only when you are signed
in, and calls to local reusable workflows only when GitHub also returns the workspace's repository; otherwise it misses
them and can warn about outputs that exist. It reports nothing for local composite actions.

## Side by side

Each case is a small repository, with its files in the tabs after flowpact's output. actionlint 1.7.12 and
`flowpact lint` ran at its root (`NO_COLOR=1`); the outputs are unchanged apart from flowpact's banner and summary.
GitHub's extension 0.31.5 ran signed in and not; what it reported is in the text.

### One matrix entry lacks a key that a reusable workflow requires

The windows entry has no `config`, so the windows leg passes an empty `config` and runs
`./scripts/integration.sh --config ""`. The `config:` key is present under `with:`, so GitHub's required-input check
passes, and so does actionlint's. GitHub's extension reports nothing. This is the incident that started flowpact.

**actionlint:** no output.

### An include entry left over after a runner upgrade starts a job of its own

An `include` entry that joins no combination becomes a new one. `os: windows-2022` matches no `os`, so it starts a job
of its own, and the windows-2025 job runs `./scripts/package.sh --format` with an empty `archive`. actionlint treats
`archive` as defined because some entries set it; GitHub's extension reports nothing. flowpact expands the matrix as
GitHub does and names the combination without the key.

**actionlint:** no output.

### An optional input decides an `if:`, and the caller leaves it out

ci.yml does not pass `push-image`, an optional string with no default, so `if: inputs.push-image` is false: the image
is built on every push to main, never published, and the run is green. actionlint and GitHub's extension report
nothing. With `type: boolean`, flowpact stays quiet too: the default is then `false`, and leaving it out is an opt-in.

**actionlint:** no output.

### A required input is fed from an optional input nobody sets

release.yml passes `environment: ${{ inputs.environment }}` to deploy.yml, but ci.yml never sets release.yml's
optional `environment`, so deploy.yml's required input arrives empty. Each file is valid on its own; the value is lost
between them. actionlint sees `environment:` present in each call; GitHub's extension reports nothing.

**actionlint:** no output.

### A local action after a checkout into a subdirectory

A step's `./` path resolves against the workspace, not the repository. The checkout writes the repository to `src`, so
nothing is at `./.github/actions/setup-node` and the step fails when it is reached. actionlint resolves `./` against the
repository root and reports nothing; neither does GitHub's extension. flowpact maps the path through the checkout and
suggests the paths that work. A typo in the path is the same rule.

**actionlint:** no output.

### A reusable workflow declares one secret and reads another

A called workflow sees only the secrets passed to it, so `./publish.sh` runs without `NPM_TOKEN`. actionlint and
flowpact both report it, at the same position: actionlint an undefined property of `secrets`, flowpact an empty value,
with the callers that do not use `secrets: inherit`. GitHub's extension reports nothing.

```yaml title=".github/workflows/publish.yml"
          REGISTRY_URL: ${{ secrets.REGISTRY_URL }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
```

</Tab>
</Tabs>

The difference shows when the repository changes:

- **publish.yml declares no secrets at all.** actionlint reports nothing, because it types the `secrets` context only
  when `on.workflow_call.secrets` declares one. flowpact reports the same `FP205`.
- **The only caller uses `secrets: inherit`.** The read works: GitHub's documentation says inherited secrets can be
  referenced even if they are not declared. actionlint still reports the error above. flowpact reports no error, and
  an `FP204` info that lists the secrets the inherit feeds.

## Beyond lint

Some breaks exist only against something the files do not show: the interface other repositories were written
against, or the commit a pull request starts from.

**Contracts.** `flowpact check` compares each workflow and action with its committed [contract](/docs/contracts). For a
reusable workflow whose callers are all elsewhere, it is the only check here that notices: after an output was removed
and a required input added, actionlint and GitHub's language server reported nothing, and `flowpact check` reported
both.

```text
✖  ERROR  FP803 breaking-interface-change
  Breaking change to .github/workflows/deploy.yml: output "deployed-version" was removed —
  consumers reading it get an empty value
```

**Impact mode.** A pull request titled `fix: tidy the test job` renamed a published workflow's job from `Test` to
`Unit tests`: callers' branch protection waits forever for the old check, and release-please ships it as a patch.
actionlint and GitHub's language server report nothing. `flowpact impact` fails until the title is
`feat!: rename the test job`. See [impact mode](/docs/impact-mode).

```text
✖  ERROR  FP810 impact-under-declared
  Declared patch (the title "fix: tidy the test job"), but the changes require major: check "… /
  Test" is now "… / Unit tests"; consumers that require the old name wait forever
```

**Trace.** `flowpact trace` follows a value down to where it is used, or with `--up` to where it comes from. actionlint
has no equivalent. On the
[`deep-nesting`](https://github.com/ciatlas/flowpact/tree/main/fixtures/deep-nesting) fixture:

```text
$ flowpact trace pipeline.yml:environment
.github/workflows/pipeline.yml#inputs.environment:5:7 (input)
└── ▶ .github/workflows/build.yml#inputs.environment:5:7 (input)
    via ${{ inputs.environment }}  @ .github/workflows/pipeline.yml:23:24
    └── ▶ .github/workflows/package.yml#inputs.environment:5:7 (input)
        via ${{ inputs.environment }}  @ .github/workflows/build.yml:31:24
        └── ▶ .github/workflows/publish.yml#inputs.environment:5:7 (input)
            via ${{ inputs.environment }}  @ .github/workflows/package.yml:27:24
            └── job setting in jobs.upload › environment  .github/workflows/publish.yml:24:22
                ${{ inputs.environment }}
```

**In the editor.** flowpact's hover shows where a value comes from and goes, and go to definition, references and
rename work across workflow calls. GitHub's language server documents the syntax on hover, and has no definition or
references. See [editors](/docs/editors).

## Where they overlap

These are reported by more than one tool, and actionlint and flowpact report them at the same positions:

- actionlint, flowpact and GitHub's extension¹ report a call to a local reusable workflow that leaves out a required
  input or secret or passes an input it does not declare, a job's `uses:` path to a workflow file that does not exist,
  a `needs` job output that does not exist or a job that is not under `needs:`, and a matrix key that no combination
  defines.
- actionlint and flowpact also report a literal of the wrong type for a typed input, a missing or misspelled input and
  an undefined output of a local composite action, and a reusable workflow that reads `matrix.*` without a matrix of
  its own.
- For calls into other repositories, GitHub's extension¹ (when signed in) and flowpact report a required input left out
  and an input or secret the callee does not declare, and actionlint does for the inputs of popular actions. GitHub's
  extension reads the callee from GitHub as you edit; flowpact reads the lockfile you commit, so the same check runs
  in CI and grades a new version before you take it.

actionlint reports a missing input in whichever file makes the call; it does not follow a value from one level to the
next, as in the `FP107` case above. On shared findings, flowpact adds the chain of calls, why it matters, how to fix
it and a "did you mean".

Both CLIs produce JSON, SARIF and pull request annotations. GitHub's extension manages runs and logs and completes
workflow syntax, which neither CLI does. flowpact's YAML, schema and expression checks (`FP502`–`FP505`) repeat the
extension's, so flowpact's VS Code extension [hides them](/docs/editors#settings) by default in files you open while it
runs.

## Use them together

| Tool | Use it for | Overlap with flowpact |
| --- | --- | --- |
| [actionlint](https://github.com/rhysd/actionlint) | Each file in depth: expression types, shell scripts (shellcheck), runner labels, cron syntax, script injection, inputs of popular actions | Direct calls to local reusable workflows and local actions, the inputs of popular actions, `needs` outputs, matrix keys no combination defines, and undeclared secrets in a workflow that declares some |
| [GitHub Actions extension](https://marketplace.visualstudio.com/items?itemName=GitHub.vscode-github-actions) (VS Code) | Writing workflows: completion, documentation on hover, validation (including cron schedules and properties of built-in contexts); runs and logs | Direct calls to local reusable workflows and calls into other repositories (when signed in), missing outputs, `env` variables nothing sets, matrix keys no combination defines; YAML, schema and expression errors (`FP502`–`FP505`) |
| [zizmor](https://github.com/zizmorcore/zizmor), ghalint | Security: injection, excessive permissions, pinning | `secrets: inherit`, which zizmor's `secrets-inherit` audit and ghalint's `deny_inherit_secrets` policy flag; flowpact's `FP204` lists the secrets the callee reads |
| gh-actions-lockfile, ghasum, actionspack, GitHub's `dependencies:` lock | Pin action and workflow **versions** (SHAs, hashes) | None — they lock *what code runs*, flowpact checks *what data flows* |
| [CodeQL for GitHub Actions](https://github.blog/security/application-security/how-to-secure-your-github-actions-workflows-with-codeql/) | Security: untrusted data followed through steps, jobs, composite actions and reusable workflows to sinks such as code injection and cache poisoning | Both follow data across files: CodeQL to where it is unsafe, flowpact to where a value arrives empty |
| [ravelact](https://github.com/wadackel/ravelact) | Exploring the graph: what an event runs, who calls a workflow, which entry points a change affects; permissions and required secrets down chains of local reusable workflows | Inputs and outputs nothing reads (`FP104`, `FP303`) and a required secret a caller leaves out (`FP201`); it leaves `with:` checks to actionlint and does not evaluate matrices |

**Recommendation:** run actionlint and flowpact together, and zizmor for security. flowpact focuses on what crosses file
boundaries and matrix combinations.

<Callout title="Same-repository $/ references">
GitHub documents `uses: $/path` for this repository at the running commit (not on GitHub Enterprise Server). actionlint
1.7.12 and GitHub's extension report it as an error, yet accept the invalid `$/path@v1` (the extension in a step only).
flowpact resolves `$/`, checks what it points to, and reports the `@ref` form. If you also run actionlint, use the `./` form of an `FP606` fix.
</Callout>
