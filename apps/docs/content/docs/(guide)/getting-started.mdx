---
title: Quickstart
description: Run flowpact on a repository, read a finding, and check the calls into other repositories.
---

A few minutes, at the root of a repository with workflows, with Node.js 22 or newer. `npx` runs flowpact without
installing it; to install it, or to start in the editor or in GitHub Actions instead, see [Install](/docs/installation).

<Steps>
<Step>
### Lint the repository

```sh
npx flowpact lint
```

There is nothing to configure. flowpact reads every workflow and every local action it reaches, and its own files when
they exist:

<Files>
  <Folder name=".github" defaultOpen>
    <Folder name="workflows" defaultOpen>
      <File name="ci.yml" />
      <File name="release.yml" />
      <File name="actions.lock" />
    </Folder>
    <Folder name="actions" defaultOpen>
      <Folder name="setup" defaultOpen>
        <File name="action.yml" />
      </Folder>
    </Folder>
    <Folder name="flowpact" defaultOpen>
      <File name="flowpact.config.yml" />
      <File name="remotes.lock.yaml" />
      <Folder name="contracts" />
    </Folder>
  </Folder>
  <File name="action.yml" />
</Files>

| File | What it is |
| --- | --- |
| `.github/workflows/*.yml` | Your workflows. |
| `action.yml` | Your local actions: under `.github/actions/`, the repository's own at the root, and any directory a `uses: ./path` points to. |
| `.github/flowpact/flowpact.config.yml` | The [config](/docs/configuration), when you need one. |
| `.github/flowpact/remotes.lock.yaml` | The interfaces of workflows and actions in other repositories (step 4). |
| `.github/flowpact/contracts/` | [Contracts](/docs/contracts), when you publish workflows. |
| `.github/workflows/actions.lock` | GitHub's own lockfile, when you have one ([what flowpact reads in it](/docs/remote-interfaces#githubs-actionslock)). |

It always analyzes the whole repository, because most problems span files. A step's `./path` is resolved through the
job's `actions/checkout` steps, since it is relative to the runner's workspace. flowpact writes nothing unless you ask
it to.
</Step>
<Step>
### Read a finding

<Screenshot name="lint-incident" alt="flowpact lint reporting FP401: input config is empty for the windows matrix combination" caption="One matrix entry has no config, so its tests never run." />

Each finding shows, top to bottom:

| Part | Meaning |
| --- | --- |
| `✖ ERROR FP401 empty-binding-for-matrix-combo` | The severity, the rule's stable code and its name. |
| message | What is wrong, in one sentence. |
| `▶ file:line:col` and the code | Where, with the expression underlined. |
| `matrix` | The matrix combinations it affects (matrix rules only). |
| `context` | Related places: the call chain from the top-level workflow, the `include` entry, the input that receives the value. |
| `why` / `fix` | Why it matters, and what to change. |
| `docs` | The rule's page (a link in terminals that support them). |

The run ends with a summary: counts per severity, the files, jobs and matrix combinations, and the most frequent codes.
`npx flowpact explain FP401` prints a rule's page in the terminal.
</Step>
<Step>
### A clean run

<Screenshot name="lint-clean" alt="flowpact lint on a repository with no findings: the summary says No problems found" caption="No findings: the summary alone, and exit code 0." />

The exit code is `0` without errors and `1` with errors (or warnings, with `--fail-on warning`). See
[exit codes](/docs/cli#exit-codes).
</Step>
<Step>
### Check the calls into other repositories

A call to a workflow or action in another repository (`uses: actions/setup-node@v6`) is checked once flowpact knows its
interface. Record the interfaces once, and commit the file:

```sh
npx flowpact remotes update     # writes .github/flowpact/remotes.lock.yaml
npx flowpact lint
```

`remotes update` reads each reference's workflow file or `action.yml` through the GitHub API, with `GH_TOKEN`,
`GITHUB_TOKEN` or your `gh` sign-in (public repositories need none). After it, a call that passes an input the action
no longer has is a finding like any other:

```text
✖  ERROR  FP102 unknown-input
  actions/setup-node@v6 has no input "always-auth"

  ▶ .github/workflows/release.yml:10:11
     8 │         with:
     9 │           node-version: 24
    10 │           always-auth: true
       │           ━━━━━━━━━━━
```

Lint reads only the committed file, so it needs no network. Run `remotes update` again when you move a reference to
another version, or on a schedule: it says what each change does to your calls
([When a version changes](/docs/remote-interfaces#when-a-version-changes)).
</Step>
<Step>
### Follow a value

```sh
npx flowpact trace pipeline.yml:config            # where does this input go?
npx flowpact trace run-suite.yml:config --up      # where does this value come from?
npx flowpact graph                                # which workflows call which
```

See [`flowpact trace`](/docs/cli#flowpact-trace) and [`flowpact graph`](/docs/cli#flowpact-graph).
</Step>
<Step>
### Narrow it down

```sh
npx flowpact lint .github/workflows/release.yml   # report on one file (all is analyzed)
npx flowpact lint --only FP401,FP101              # run some rules
npx flowpact lint --hide-info                     # list errors and warnings only
```

A first run on a large repository can list many findings: [Adopt it in an existing repository](/docs/adopting) says
where to start.
</Step>
</Steps>
