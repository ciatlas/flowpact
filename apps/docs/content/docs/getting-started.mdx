## Install

flowpact needs Node.js 22 or newer. The npm package and the command are both `flowpact`.

<Tabs items={["Global", "Project (npm)", "Project (pnpm)", "One-off", "mise"]}>
<Tab value="Global">
Install once and use `flowpact` anywhere:

```sh
npm install --global flowpact
flowpact lint
```
</Tab>
<Tab value="Project (npm)">
Pin the version for everyone working on the repository (and its CI):

```sh
npm install --save-dev flowpact
npx flowpact lint
```
</Tab>
<Tab value="Project (pnpm)">
```sh
pnpm add -D flowpact
pnpm flowpact lint
```
</Tab>
<Tab value="One-off">
```sh
npx flowpact@0.17 lint
```
</Tab>
<Tab value="mise">
```sh
mise use --global npm:flowpact
flowpact lint
```
</Tab>
</Tabs>

In GitHub Actions, use the [action](/docs/action) instead: it needs neither Node.js nor an install.

In VS Code, install the extension from the
[Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=flowpact.vscode-flowpact), or from
[Open VSX](https://open-vsx.org/extension/flowpact/vscode-flowpact) in VSCodium, Cursor, Windsurf and other editors built
on VS Code. It bundles the language server, so it needs neither Node.js nor the npm package.

## First run

<Steps>
<Step>
### Lint the repository

```sh
flowpact lint
```

flowpact reads `.github/workflows/*.yml` and every local action (`action.yml` under `.github/actions/`, the
repository's own `action.yml` at the root, plus any other directory a `uses: ./path` or `uses: $/path` points to; a
step's `./path` is mapped through the job's `actions/checkout` steps, since it is relative to the runner's workspace).
It always loads the whole repository, because most problems span files.
</Step>
<Step>
### Read a finding

Each finding shows, top to bottom:

| Part | Meaning |
| --- | --- |
| `✖ ERROR FP401 empty-binding-for-matrix-combo` | severity, stable code and rule name |
| message | what is wrong, in one sentence |
| `▶ file:line:col` + code frame | exactly where, with the expression underlined |
| `matrix` | the affected matrix combinations (matrix rules only) |
| `context` | related locations — the call chain from the top-level workflow, the include entry, the receiving input |
| `why` / `fix` | why it matters and what to change |
| `docs` | a link to the rule page (clickable in terminals that support hyperlinks) |

The run ends with a summary card: counts per severity, files, jobs, matrix combinations, graph size and the most
frequent codes.
</Step>
<Step>
### Dig deeper

```sh
flowpact explain FP401                      # why/fix/examples for a code
flowpact trace pipeline.yml:config           # where does this input go?
flowpact trace run-suite.yml:config --up     # where does this value come from?
```
</Step>
<Step>
### Narrow it down

```sh
flowpact lint .github/workflows/release.yml  # only report on some files (everything is still analyzed)
flowpact lint --only FP401,FP101           # only run some rules
flowpact lint --hide-info                    # list errors and warnings only
```
</Step>
</Steps>

## Next steps

<Steps>
<Step>
### See findings as you type

Install the extension from the
[Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=flowpact.vscode-flowpact) or
[Open VSX](https://open-vsx.org/extension/flowpact/vscode-flowpact). It reports the same findings while you edit,
unsaved changes included, and shows on hover where a value comes from and where it goes. Other editors: see
[editors](/docs/editors).
</Step>
<Step>
### Lock the interfaces

```sh
flowpact generate        # write .github/flowpact/**/*.contract.yml
git add .github/flowpact && git commit -m "Add workflow contracts"
flowpact check           # lint + compare with the committed contracts
```

[Contracts](/docs/contracts) make every change to an input, secret, output or call visible in review, and `flowpact check`
fails on breaking changes. If other repositories use your workflows or actions, [impact mode](/docs/impact-mode) also
fails a pull request whose title declares less than the minor or major release its changes need.
</Step>
<Step>
### Run it in CI

Add the [GitHub Action](/docs/action) or the CLI to a workflow — see [CI usage](/docs/ci).
</Step>
<Step>
### Tune it

Change severities, accept specific findings with a reason and an expiry date, or add your own rules in the
[configuration](/docs/configuration).
</Step>
</Steps>

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | No findings at or above `--fail-on` (default: `error`) |
| `1` | Findings at or above `--fail-on` (in `flowpact check`, this includes contract drift) |
| `2` | Usage or configuration error (unknown rule, invalid config, plugin that fails to load, nothing to analyze) |
| `3` | Internal error — please [report it](https://github.com/ciatlas/flowpact/issues) with `--debug` output |
