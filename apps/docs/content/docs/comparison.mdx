title: Comparison
description: What flowpact reports that actionlint and GitHub's VS Code extension do not, with actionlint's and flowpact's output side by side, and where the tools overlap.
---

flowpact reports what happens between files and between matrix combinations: values that are present in the YAML but
arrive empty, because one `include` entry lacks a key, an optional input is never set, or a called workflow reads a
secret while declaring none. GitHub raises no error for these and the run carries on, and neither actionlint nor
GitHub's VS Code extension reports them. Where the checks overlap, on direct calls to a local reusable workflow or local
action, flowpact adds the chain of calls, why it matters, how to fix it and a link to the rule. actionlint checks each
file in more depth (shell scripts, expression types, runner labels), so use both.

What each tool reports, from small test repositories and the tools' own documentation:

| Problem | actionlint | GitHub Actions extension¹ | flowpact |
| --- | --- | --- | --- |
| One matrix combination passes an empty value, because an `include` entry lacks a key | — | — | ✓ names the combination ([`FP401`](/docs/rules/fp401), [`FP402`](/docs/rules/fp402)) |
| An optional input with no default is left out: a step is skipped, or a required input further down gets `''` | — | — | ✓ [`FP105`](/docs/rules/fp105), [`FP107`](/docs/rules/fp107) |
| A reusable workflow reads a secret it does not declare | only if it declares other secrets; also reports reads that `secrets: inherit` makes valid | — | ✓ counts the callers that do not inherit ([`FP205`](/docs/rules/fp205)) |
| A step's local action is not where the step runs: a path typo, or a checkout into a subdirectory | — | — | ✓ [`FP606`](/docs/rules/fp606) |
| A composite action reads an input it does not declare | — (does not lint `action.yml`) | — | ✓ suggests the declared name ([`FP108`](/docs/rules/fp108)) |
| An output arrives empty: its step never writes it, or a nested workflow no longer has it | — | nested workflow only | ✓ [`FP304`](/docs/rules/fp304), [`FP301`](/docs/rules/fp301) |
| A matrix built with `fromJSON` is read with a key it never has | — | — | ✓ once you declare its keys ([`FP403`](/docs/rules/fp403), [`FP404`](/docs/rules/fp404)) |
| GitHub rejects the run: a call cycle, a call chain of more than 10 workflows, more than 256 matrix jobs | — | — | ✓ [`FP601`](/docs/rules/fp601), [`FP602`](/docs/rules/fp602), [`FP406`](/docs/rules/fp406) |
| Inputs, outputs and secrets nothing reads, and which secrets a `secrets: inherit` call actually needs | — | — | ✓ [`FP104`](/docs/rules/fp104), [`FP106`](/docs/rules/fp106), [`FP203`](/docs/rules/fp203), [`FP303`](/docs/rules/fp303), [`FP204`](/docs/rules/fp204) |
| A published workflow changes an input, an output or a check name that consumers in other repositories may depend on | — | — | ✓ against the committed [contract](/docs/contracts) (`FP803`) or the pull request's base in [impact mode](/docs/impact-mode) (`FP810`); it does not read the consumers |
| Where a value comes from and where it goes, across files | — | — (no go to definition or references) | ✓ `flowpact trace`, hover, go to definition, references |
| A workflow reads an `env` variable that nothing sets | — | ✓ also warns on a valid `$GITHUB_ENV` write earlier in the job | only if no action step, such as `actions/checkout`, comes before the read ([`FP501`](/docs/rules/fp501)) |
| A call to a local reusable workflow or local action leaves out a required input or secret, or passes an unknown input or a literal of the wrong type | ✓ | local reusable workflows only, when signed in; no type check | ✓ suggests the declared name ([`FP101`](/docs/rules/fp101)–[`FP103`](/docs/rules/fp103), [`FP201`](/docs/rules/fp201)) |
| A matrix key that no combination defines | ✓ | ✓ | ✓ [`FP404`](/docs/rules/fp404) |
| A `${{ }}` expression that does not parse, or calls a function with the wrong number of arguments | ✓ | ✓ | ✓ [`FP502`](/docs/rules/fp502) |
| A context used where GitHub does not allow it, such as `secrets` in a job's `if:` | ✓ | ✓ | ✓ [`FP505`](/docs/rules/fp505) |
| A call to an action or reusable workflow in another repository passes an unknown input | ✓ for popular actions such as `actions/checkout`; not for reusable workflows | not compared | — (a call to a reusable workflow in another repository is reported as unverified, [`FP603`](/docs/rules/fp603)) |
| A property that a built-in context does not have, such as `github.reff` or `runner.oss` | ✓ | ✓ as a warning | — |
| An expression whose type does not fit, such as `${{ github.ref_name }}` (a string) in `timeout-minutes`, or an object in `${{ }}` | ✓ | — (only a literal such as `${{ 'abc' }}`) | — (only a literal, [`FP503`](/docs/rules/fp503)) |
| A cron schedule that is invalid (hour 25) or runs more often than every 5 minutes | ✓ | ✓ | — |
| A runner label that does not exist, such as `ubuntu-latst`, or was retired, such as `ubuntu-18.04` | ✓ | — | — |
| Bugs in `run:` scripts, such as an unquoted variable | ✓ runs shellcheck when it is installed | — | — |
| Security: script injection, permissions, pinning ([zizmor](https://github.com/zizmorcore/zizmor) covers these) | script injection and hard-coded credentials | not compared | — |

¹ GitHub Actions extension 0.31.5, run through its language server. It checks calls to local reusable workflows only
when you are signed in to GitHub and GitHub returns the repository of the workspace's git remote; without that it misses
them and can warn about outputs that do exist. It reports nothing for local composite actions.

## Side by side

Each case is a small repository of its own. actionlint 1.7.12 ran from the repository root and flowpact ran
`flowpact lint` with `NO_COLOR=1`. The outputs are copied unchanged, without the version banner and `root` line that
flowpact prints first and its closing summary. GitHub's Actions extension 0.31.5 ran through its language server, with
the repository resolved as when you are signed in and without; what it reported is in the text.

### One matrix entry lacks a key that a reusable workflow requires

The windows entry has no `config`. GitHub evaluates a missing matrix key to an empty string, so the windows leg calls
integration.yml with an empty `config` and runs `./scripts/integration.sh --config ""`. The `config:` key is present
under `with:`, so GitHub's required-input check passes and the run raises no error. actionlint makes the same check:
delete the `config:` line and it reports the missing input, but an empty value in one combination passes. GitHub's
extension reports nothing. It is the same mistake as the incident that started flowpact.

```yaml title=".github/workflows/ci.yml"
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  integration:
    strategy:
      matrix:
        include:
          - platform: linux
            runner: ubuntu-latest
            config: ci/linux.json
          - platform: macos
            runner: macos-latest
            config: ci/macos.json
          - platform: windows
            runner: windows-latest
    uses: ./.github/workflows/integration.yml
    with:
      runner: ${{ matrix.runner }}
      config: ${{ matrix.config }}
```

```yaml title=".github/workflows/integration.yml"
name: Integration tests
on:
  workflow_call:
    inputs:
      runner:
        type: string
        required: true
      config:
        type: string
        required: true

jobs:
  test:
    runs-on: ${{ inputs.runner }}
    steps:
      - uses: actions/checkout@v4
      - run: ./scripts/integration.sh --config "${{ inputs.config }}"
```

**actionlint:** no output.

**flowpact:**


### An include entry left over after a runner upgrade starts a job of its own

GitHub adds each `include` entry to every combination it can join without overwriting a value; an entry that joins none
becomes a new combination. `os: windows-2022` matches no `os` in the matrix, so it becomes a separate windows-2022 job,
and the windows-2025 job has no `archive`. That job runs `./scripts/package.sh --format` with an empty value. actionlint
treats `archive` as defined because some entries set it, and GitHub's extension reports nothing. flowpact expands the
matrix with GitHub's rules and names the one combination without the key.

```yaml title=".github/workflows/package.yml"
name: Package
on:
  push:
    tags: ['v*']

jobs:
  package:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-24.04, macos-15, windows-2025]
        include:
          - os: ubuntu-24.04
            archive: tar.gz
          - os: macos-15
            archive: tar.gz
          - os: windows-2022
            archive: zip
    steps:
      - uses: actions/checkout@v4
      - run: ./scripts/package.sh --format ${{ matrix.archive }}
        shell: bash
```

**actionlint:** no output.

**flowpact:**


### An optional input decides an `if:`, and the caller leaves it out

An optional string input without a default is an empty string when the caller omits it. ci.yml does not pass
`push-image`, so `if: inputs.push-image` is false and the push step is skipped on every push to main: the image is
built, never published, and the run is green. actionlint and GitHub's extension report nothing. With `type: boolean`
flowpact reports nothing, because the default is then `false` and leaving the input out is a deliberate opt-in.

```yaml title=".github/workflows/ci.yml"
name: CI
on:
  push:
    branches: [main]

jobs:
  release:
    uses: ./.github/workflows/release.yml
    with:
      version: ${{ github.sha }}
```

```yaml title=".github/workflows/release.yml"
name: Release
on:
  workflow_call:
    inputs:
      version:
        type: string
        required: true
      push-image:
        description: Push the image to the registry after building it
        type: string
        required: false

jobs:
  image:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t "ghcr.io/acme/app:${{ inputs.version }}" .
      - if: inputs.push-image
        run: docker push "ghcr.io/acme/app:${{ inputs.version }}"
```

**actionlint:** no output.

**flowpact:**

```text
── .github/workflows/release.yml ──────────────────────────────────────────────────────── 1 warning

▲  WARN  FP105 optional-input-no-default-in-condition
  Condition reads optional input "push-image", which has no default and is '' when omitted

  ▶ .github/workflows/release.yml:19:13
    17 │       - uses: actions/checkout@v4
    18 │       - run: docker build -t "ghcr.io/acme/app:${{ inputs.version }}" .
    19 │       - if: inputs.push-image
       │             ━━━━━━━━━━━━━━━━━

  fix     Give the input an explicit `default`, make it `required: true`, or compare explicitly
```

### A required input is fed from an optional input nobody sets

release.yml passes `environment: ${{ inputs.environment }}`, so its call to deploy.yml looks complete and GitHub starts
the run. ci.yml never sets release.yml's optional `environment`, which has no default, so deploy.yml's required
`environment` arrives as an empty string. Each file is valid on its own; the value is lost between them. actionlint
reads the interface of each direct callee, finds `environment:` present and reports nothing. GitHub's extension reports
nothing either.

```yaml title=".github/workflows/ci.yml"
on: push
jobs:
  release:
    uses: ./.github/workflows/release.yml
```

```yaml title=".github/workflows/release.yml"
on:
  workflow_call:
    inputs:
      environment:
        type: string
        required: false
jobs:
  deploy:
    uses: ./.github/workflows/deploy.yml
    with:
      environment: ${{ inputs.environment }}
```

```yaml title=".github/workflows/deploy.yml"
on:
  workflow_call:
    inputs:
      environment:
        type: string
        required: true
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - run: echo "deploying to ${{ inputs.environment }}"
```

**actionlint:** no output.

**flowpact:**

```text
── .github/workflows/release.yml ──────────────────────────────────────────────────────── 1 warning

▲  WARN  FP107 optional-forwarded-to-required
  Required input "environment" of .github/workflows/deploy.yml is fed from optional input
  "environment" without a default

  ▶ .github/workflows/release.yml:11:24
     9 │     uses: ./.github/workflows/deploy.yml
    10 │     with:

       │                        ━━━━━━━━━━━━━━━━━━

```

### A composite action reads a misspelled input

`inputs.enviroment` is not declared, so it evaluates to an empty string, and the action runs
`./scripts/deploy.sh --env ""` although the caller passes `environment: production`. actionlint lints workflow files,
not `action.yml`, and reports nothing; GitHub's extension reports nothing for either file. flowpact reports the typo
and suggests the declared name, and reports that the declared input is never read.

```yaml title=".github/workflows/deploy.yml"
name: Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/deploy
        with:
          environment: production
```

```yaml title=".github/actions/deploy/action.yml"
name: Deploy
description: Deploy the site to one environment
inputs:
  environment:
    description: Target environment
    required: true
runs:
  using: composite
  steps:
    - shell: bash
      run: ./scripts/deploy.sh --env "${{ inputs.enviroment }}"
```

**actionlint:** no output.

### A local action after a checkout into a subdirectory

A step's `./` path resolves against the runner's workspace, not the repository. The checkout writes this repository to
`src`, so the action is at `./src/.github/actions/setup-node`, nothing is at `./.github/actions/setup-node`, and the
step fails when it is reached. actionlint resolves `./` against the repository root, where the action exists, and
reports nothing; neither does GitHub's extension. flowpact maps the path through the checkout and suggests the paths
that work. A typo in a step's action path, such as `./.github/actions/setup-nod`, is the same rule, and the other two
tools report nothing there either.

```yaml title=".github/workflows/ci.yml"
on: push
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          path: src
      - uses: ./.github/actions/setup-node
      - run: npm test
        working-directory: src
```

```yaml title=".github/actions/setup-node/action.yml"
name: Setup Node
description: Install Node and dependencies
runs:
  using: composite
  steps:
    - uses: actions/setup-node@v4
      with:
        node-version: 22
    - run: npm ci
      shell: bash
```

**actionlint:** no output.

**flowpact:**


### A reusable workflow declares one secret and reads another

Both tools report this one, at the same position. A called workflow sees only the secrets passed to it, so
`secrets.NPM_TOKEN` is empty and `./publish.sh` runs without a token. actionlint reports an undefined property of the
`secrets` object and looks no further than publish.yml. flowpact says the value will be empty and counts the callers
that do not use `secrets: inherit`. GitHub's extension reports nothing.

```yaml title=".github/workflows/ci.yml"
on: push
jobs:
  publish:
    uses: ./.github/workflows/publish.yml
    secrets:
      REGISTRY_URL: ${{ secrets.REGISTRY_URL }}
```

```yaml title=".github/workflows/publish.yml"
on:
  workflow_call:
    secrets:
      REGISTRY_URL:
        required: true
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - run: ./publish.sh
        env:
          REGISTRY_URL: ${{ secrets.REGISTRY_URL }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
```

**actionlint:**

```text
.github/workflows/publish.yml:13:26: property "npm_token" is not defined in object type {actions_runner_debug: string; actions_step_debug: string; github_token: string; registry_url: string} [expression]
   |
13 |           NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
   |                          ^~~~~~~~~~~~~~~~~
```

**flowpact:**

```text
── .github/workflows/publish.yml ────────────────────────────────────────────────────────── 1 error

✖  ERROR  FP205 undeclared-secret-ref
  .github/workflows/publish.yml reads secrets.NPM_TOKEN, which is not declared — it is empty when
  called from 1 caller without `secrets: inherit`

  ▶ .github/workflows/publish.yml:13:26
    11 │         env:
    12 │           REGISTRY_URL: ${{ secrets.REGISTRY_URL }}
    13 │           NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
       │                          ━━━━━━━━━━━━━━━━━

  context └─ .github/workflows/ci.yml:4:11  .github/workflows/ci.yml › jobs.publish passes explicit secrets
  why     Inside a called workflow only declared (or inherited) secrets exist. Reading anything
          else yields an empty string, so authentication steps fail late or, worse, fall back to
          anonymous access.
  fix     Declare the secret under `on.workflow_call.secrets` and pass it from every caller, or
          use `secrets: inherit`. Callers whose `with:` values make the reading job's or step's
          `if:` false (e.g. an omitted input in `if: contains(inputs.registries, 'docker.io')`)
          are not counted: the read never runs for them.
  docs    https://ciatlas.github.io/flowpact/docs/rules/fp205
```

The difference shows when the repository changes:

- **publish.yml declares no secrets at all.** actionlint reports nothing, because it types the `secrets` context only
  when `on.workflow_call.secrets` declares one. flowpact reports the same `FP205`.
- **The only caller uses `secrets: inherit`.** The read works: GitHub's documentation says inherited secrets can be
  referenced even if they are not declared. actionlint still reports the error above. flowpact reports no error, and
  an `FP204` info that lists the secrets the inherit feeds.

## Beyond lint

Some breakages exist only relative to something the current files do not show: the interface that other repositories
were written against, or the commit a pull request starts from.

**Contracts.** `flowpact generate` writes each workflow's and action's interface to a contract file that you commit,
and `flowpact check` reports a change that breaks it. It compares the workflow with its committed contract, not with
the callers, which it cannot see when they live in other repositories. For a reusable workflow whose callers are all
elsewhere, it is the only check here that notices: after an output was removed and a required input added, actionlint
printed nothing, GitHub's language server published 0 diagnostics, and `flowpact check` reported both changes, as did
flowpact's language server while the file was open. `flowpact lint` does not report the removed output; `check` does.
See [contracts](/docs/contracts).

```text
✖  ERROR  FP803 breaking-interface-change
  Breaking change to .github/workflows/deploy.yml: output "deployed-version" was removed —
  consumers reading it get an empty value
```

**Impact mode.** A pull request titled `fix: tidy the test job` renamed a job in a published reusable workflow from
`Test` to `Unit tests`. Consumers whose branch protection requires the old check name then wait for it forever, and a
release tool that reads the title, such as release-please, ships the change as a patch to everyone on `@v1`. actionlint
and GitHub's language server report nothing. `flowpact impact` fails; retitled `feat!: rename the test job`, the same
change passes. See [impact mode](/docs/impact-mode).

```text
✖  ERROR  FP810 impact-under-declared
  Declared patch (the title "fix: tidy the test job"), but the changes require major: check "… /
  Test" is now "… / Unit tests"; consumers that require the old name wait forever
```

**Trace.** `flowpact trace` follows a value through reusable workflows down to where it is used, or with `--up` back to
where it comes from. actionlint has no equivalent. On the
[`deep-nesting`](https://github.com/ciatlas/flowpact/tree/main/fixtures/deep-nesting) fixture:

```text
$ flowpact trace pipeline.yml:environment
.github/workflows/pipeline.yml#inputs.environment:5:7 (input)
└── ▶ .github/workflows/build.yml#inputs.environment:5:7 (input)
    via ${{ inputs.environment }}  @ .github/workflows/pipeline.yml:23:24
    └── ▶ .github/workflows/package.yml#inputs.environment:5:7 (input)
        via ${{ inputs.environment }}  @ .github/workflows/build.yml:31:24
        └── ▶ .github/workflows/publish.yml#inputs.environment:5:7 (input)
            via ${{ inputs.environment }}  @ .github/workflows/package.yml:27:24
            └── job setting in jobs.upload › environment  .github/workflows/publish.yml:24:22
                ${{ inputs.environment }}
```

**In the editor.** flowpact's hover shows where a value comes from and where it goes, and go to definition and find
references work across workflow calls. GitHub's Actions language server documents the syntax on hover; it declares no
definition or references provider and answers both requests with "Unhandled method". See [editors](/docs/editors).

## Where they overlap

These are reported by more than one tool, and actionlint and flowpact report them at the same positions:

- actionlint, flowpact and GitHub's extension¹ report a call to a local reusable workflow that leaves out a required
  input or secret or passes an input it does not declare, a job's `uses:` path to a workflow file that does not exist,
  a `needs` job output that does not exist or a job that is not under `needs:`, and a matrix key that no combination
  defines.
- actionlint and flowpact also report a literal of the wrong type for a typed input, a missing or misspelled input and
  an undefined output of a local composite action, and a reusable workflow that reads `matrix.*` without a matrix of
  its own.

A missing input deep in a chain belongs to the first group: actionlint lints every file, so it reports the call in
whichever file makes it. What it does not do is follow a value from one level to the next, as in the `FP107` case
above.

On these findings flowpact adds context: the chain of calls that reaches the file, why the value matters, how to fix
it, a link to the rule, and a "did you mean" for a misspelled name, where actionlint lists every declared name.

Both CLIs produce JSON, SARIF and pull request annotations: actionlint through `-format` templates, a problem matcher or
reviewdog, flowpact through `--format` and the [Action](/docs/action), which also writes a job summary. GitHub's
extension does what neither CLI does: it manages runs and logs, and completes workflow syntax, including, when you are
signed in, the outputs of a called reusable workflow. flowpact's YAML, schema and expression checks (`FP502`–`FP505`)
repeat the extension's, so flowpact's VS Code extension by default [hides them](/docs/editors#settings) in the files you
open while the GitHub extension runs.

## Use them together

| Tool | Use it for | Overlap with flowpact |
| --- | --- | --- |
| [actionlint](https://github.com/rhysd/actionlint) | Each file in depth: expression types, shell scripts (shellcheck), runner labels, cron syntax, script injection, inputs of popular actions | Direct calls to local reusable workflows and local actions, `needs` outputs, matrix keys no combination defines, and undeclared secrets in a workflow that declares some |
| [GitHub Actions extension](https://marketplace.visualstudio.com/items?itemName=GitHub.vscode-github-actions) (VS Code) | Writing workflows: completion, documentation on hover, validation (including cron schedules and properties of built-in contexts); runs and logs | Direct calls to local reusable workflows (when signed in), missing outputs, `env` variables nothing sets, matrix keys no combination defines; YAML, schema and expression errors (`FP502`–`FP505`) |
| [zizmor](https://github.com/zizmorcore/zizmor), ghalint | Security: injection, permissions, pinning | `secrets: inherit`, which zizmor's `secrets-inherit` audit and ghalint's `deny_inherit_secrets` policy flag; flowpact's `FP204` lists the secrets the callee reads |
| gh-actions-lockfile, ghasum, actionspack, GitHub's `dependencies:` lock | Pin action and workflow **versions** (SHAs, hashes) | None — they lock *what code runs*, flowpact checks *what data flows* |

**Recommendation:** run actionlint and flowpact together, and zizmor for security. flowpact focuses on what crosses file
boundaries and matrix combinations.

<Callout title="Same-repository $/ references">
GitHub documents `uses: $/path` for this repository at the running commit (not on GitHub Enterprise Server). actionlint
1.7.12 and GitHub's extension report it as an error, so actionlint never checks the workflow or action it points to.
actionlint accepts the invalid `$/path@v1`, in a step and in a job's `uses:`; GitHub's extension accepts it in a step.
flowpact resolves `$/`, checks the workflow or action it points to, and reports the `@ref` form. Some `FP606` fixes
suggest `$/`; if you also run actionlint, use the `./` form they offer.
</Callout>
